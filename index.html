01. E-Commerce Web Application

CLICK THE LINK AND TRY IT NOW ↗

A full-stack e-commerce prototype created to help promote and sell handmade, tailored traditional clothing.

The problem

My mother relied on third-party marketplaces such as Shopee, where commission fees, taxes, promotions, and coupons could reduce the effective selling price. This project explored an independent store that gives her greater control of pricing, promotions, and customer transactions.

What I made

I built an enterprise-style application with JHipster, Spring Boot, and Vue.js. A Java REST API connects the frontend and backend, MySQL manages application, customer, and product data, and WhatsApp supports communication and transactions between customers and the seller.

Constraints & lessons

JHipster's generated structure required substantial storage and hosting resources, so the prototype remained unhosted due to budget constraints. I also learned the importance of designing the relational schema before generating entities, because later regeneration can overwrite custom changes.

Outcome

The completed prototype demonstrated the intended e-commerce workflow and helped my mother understand how an independently managed online store could showcase products and handle orders.

Technologies: Java, Spring Boot, JHipster, Vue.js, TypeScript, REST API, MySQL, SCSS, Git, WhatsApp

02. Sign Language Learning & Translation Web Application

CLICK THE LINK AND TRY IT NOW ↗

A publicly accessible ASL-learning application with optional accounts, learning material, quizzes, a dictionary, and sign-to-text and text-to-sign translation.

The problem

Limited knowledge of sign language can make communication with members of the Deaf community more difficult. Sign-language education is not widely incorporated into institutions, while some existing resources are passive or constrained by recognition accuracy.

What I made

I chose Django because its Python ecosystem made it practical to combine web features and machine learning. Users can explore guided signs, test their memory through quizzes, search a sign dictionary, and use translation features. Camera-captured hand signs are recognised from different angles and converted into predictions.

Constraints & lessons

Motion-capture-quality data and equipment were unavailable, so images were used as the dataset. Recognition accuracy depended on the quantity and diversity of training images; hosting and database limits restricted both.

Outcome

The website was published publicly and demonstrated how machine learning and web development can create a more interactive way to learn basic sign language.

Technologies: Python, Django, HTML, CSS, JavaScript, MySQL, TensorFlow, PyTorch, MediaPipe, Git

06. Oil Palm Leaf Disease Detection

CLICK THE LINK AND TRY IT NOW ↗

A web-based prototype that classifies uploaded oil-palm leaf images as brown spots, healthy, or white scale with an EfficientNetB0 model.

The problem

Oil-palm disease can affect health, yield, and profitability. Manual visual inspection may be slow, subjective, and dependent on specialist knowledge, especially when early symptoms are subtle.

What I made

I built an interactive Streamlit app that resizes an uploaded JPG or PNG to 224×224, runs prediction through TensorFlow/Keras, shows confidence and the top three results, and estimates a Healthy, Mild, Moderate, or Severe status. The status is an accessible screening aid, not a diagnosis.

Constraints & lessons

The system supports only three classes and is sensitive to image quality, lighting, angle, and relevance. Severity is inferred from classifier confidence and uncertainty rather than a separately trained model. The 31 MB model and TensorFlow runtime make deployment heavier, while the repository lacks training data, field validation, and evaluation metrics.

Outcome

The prototype delivers an end-to-end workflow for image upload, preprocessing, classification, confidence scoring, top-three probabilities, severity estimation, and user-facing alerts. It is best positioned as a proof of concept pending broader data, testing, validation, and deployment work.

Technologies: Python, Streamlit, TensorFlow, Keras, EfficientNetB0, NumPy, Pillow, Matplotlib, JSON, HDF5, Protocol Buffers, Git

07. Digital Piano Application

CLICK THE LINK AND TRY IT NOW ↗

A desktop digital piano built with C++ and JUCE, featuring sampled audio, MIDI playback, and a Synthesia-style falling-notes visualiser.

The problem

Learning piano can be difficult without a physical piano or MIDI keyboard. Basic virtual pianos may lack realistic sound, useful controls, or clear guidance for practising MIDI songs.

What I made

The application lets users play a sampled 88-key piano with an on-screen or computer keyboard, change octaves, control volume, and enable sustain. It loads MIDI files, supports play, pause, stop, seeking, and 0.25×–2× speed, then synchronises playback with active-key highlighting and falling notes.

Constraints & lessons

The Salamander Grand Piano library contains hundreds of WAV files, so the engine loads six selected velocity layers rather than all sixteen. Real-time audio required separating processing from UI work: the audio callback drives MIDI timing, while the interface polls state for visual updates. The current build focuses on mouse and computer-keyboard input, with no external MIDI controller support, recording, advanced pedal handling, or full MIDI-event interpretation.

Outcome

The completed application provides realistic sampled playback, MIDI-song controls, synchronized falling-note guidance, and saved volume and octave preferences for casual playing and practice.

Technologies: C++, CMake, JUCE Framework, WAV Audio Samples, MIDI File Parsing, Real-Time Audio Processing, Audio Synthesis, GUI Development, STL, Git
